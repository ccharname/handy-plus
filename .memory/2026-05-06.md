### 踩过的坑

1. **DeltaComputer 在 chunked 模式不适用**（M2.6 cumulative-partial 假设 vs M2 chunked 独立片段）
   - chunk N partial = "切换一下"，chunk N+1 partial = "一下我们"，无 prefix 关系 → 全被 Action::Skip 吞
   - 修法：chunked drainer 直接 sink.append，不走 DeltaComputer
   - 一般化：streaming primitive 设计时假设的 "cumulative growing partial" 不能套用到 "independent chunk transcripts"

2. **Tauri-managed AudioRecorder 字段被 worker 一次性 clone 后失联**
   - `streaming_frame_cb: Option<...>` 在 open() 时 clone 给 worker，set_streaming_frame_callback 改主结构但 worker 不知道
   - 修法：`Arc<Mutex<Option<...>>>`，worker 每帧 lock 读
   - 一般化：跨 long-lived thread 的可变共享必须用 Arc<Mutex<>> / ArcSwap，不要靠 builder-time clone

3. **stop semantics: drain 队列 ≠ 用户期望的"立即停"**
   - drainer 收到 stop signal 还要先把 channel 里 5-10 个 chunk drain 完才退出
   - 期间 orchestrator 还在 emit 新 partial（"嗯。" hallucination）→ 持续屏上写
   - 修法：stop 时 orchestrator.cancel() + drainer 不 drain，直接 finalize sink + break
   - 一般化：M3 final pass 是 authoritative source，late streaming partials 是噪音

4. **incremental_paste_cursor 必须时刻反映屏幕真实状态**
   - M3 take cursor → reconcile sink ops → 只 push 部分内容回 cursor → actions.rs T7Output 看到 stale cursor → 又写一遍 → 屏上 double
   - 修法：M3 reconcile 完无条件 `append_incremental_paste(&final_text)`
   - 一般化：cursor 是 contract（"屏幕已 paste 文本"），任何 modify 屏幕的代码都要同步 cursor

5. **macOS pure-modifier keyup 是 handy_keys lib 工作的前提**
   - tauri-plugin-global-shortcut（Carbon RegisterEventHotKey）对单 modifier 不 fire keyup
   - 但 handy_keys (CGEventTap) 直接拿 raw keyboard event，单 modifier 双向都 fire
   - 实测：Right Cmd 在 v2t 下 handy_keys 正常工作（log 有 Pressed + Released）
   - 注意：bundle id 一变，所有 macOS 权限都需要重授（Accessibility / Input Monitoring 等）

6. **chunked streaming 的纯静音 chunk 必须抑制**
   - 否则用户说完话还按着键 → chunker 每 1.5s emit 一个 silence chunk → Qwen3-ASR hallucinate "嗯。" → 持续追加
   - 修法：track had_speech_since_last_emit 标记，无 speech 不 emit chunk
   - 第一个 silence-after-speech chunk 还需保留（end-of-utterance 边界，给模型 silence context）

7. **coordinator stage state 必须容纳 press-during-Processing**
   - 用户释放后 stage=Processing 1秒，期间 press 全被 ignore
   - 视觉上像"按了没反应" → 用户疑惑要不要再按一次
   - 修法：pending_press queue + ProcessingFinished 时 replay
   - release 取消 pending（短 tap 不应触发）
